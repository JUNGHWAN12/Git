# 🪟 Windows 학교 PC 실행 환경 명세
### 「커밋 크래프트」 실행 대상: Windows PC (학교 컴퓨터실)

> 확정 사항: **게임은 Windows PC에서 실행한다. 엔진은 Godot 4.7.2** ([Godot 아키텍처](GODOT_ARCHITECTURE.md)). 배포는 ① Windows 실행 파일(exe) ② 웹 내보내기(Edge/Chrome) 두 가지. 크롬북·태블릿·모바일 대응은 MVP 범위에서 제외한다.
> 이 문서는 ① 게임을 학교 Windows PC에서 문제없이 돌리는 법, ② 에필로그에서 **실제 Git을 Windows에 설치·사용**하는 법을 다룬다.

## 2. 학교 컴퓨터실 특유의 문제와 대응

| 문제 | 영향 | 대응 |
|---|---|---|

| 협업 서버를 선생님 PC에서 열 때 Windows 방화벽 창 | 허용하려면 관리자 권한이 필요할 수 있음 → 학생 접속 불가 | 전산 담당에게 게임 exe 또는 포트 8910 허용 요청. 안 되면 인터넷 서버 방식 ([협업 설계 2장](MULTIPLAYER_DESIGN.md)) |
| 교내망에서 PC끼리 통신 차단 | 교실 서버 방식 불가 | P0 ④ 탭으로 확인 → 인터넷 서버 방식 |
| 화면 배율 125%·150% | UI 넘침 | 배율 100/125/150%에서 레이아웃 테스트 (P5) |

### 2.1 오프라인판 = Windows 실행 파일 (Godot)
- Godot Windows 내보내기에서 **PCK 내장**을 켜서 exe 1개로 만든다 (`커밋크래프트.exe`).
- 설치 과정 없음. 교사가 교내 공유 폴더·USB에 복사 → 학생은 더블클릭.
- 크기 목표: 150MB 이하 (엔진 포함). 공유 폴더에서 바로 실행이 느리면 바탕화면에 복사해 실행 (복원 프로그램이 재부팅 때 지움).
- 외부 접속 없음 (완전 오프라인 동작).

### 2.2 진도 코드 형식
- 12자 영문 대문자+숫자 (헷갈리는 `0/O`, `1/I` 제외), 4자씩 끊어 표시: `K7QM-2XPA-9RTD`
- 담는 정보: 클리어한 스테이지(34비트), 별점(스테이지당 2비트), 검증용 체크 문자
- 코드만으로 진도 복원 가능 (서버 없음). 개인정보 없음.

## 3. 한글 입력·표시 (Windows 한국어 IME)

| 항목 | 기준 |
|---|---|
| 입력창 | Godot `LineEdit`(한 줄) / `TextEdit`·`CodeEdit`(여러 줄) — 조합 중 글자 처리는 엔진 IME 지원에 맡김 |
| 조합 중 Enter | 조합 중인 글자가 있을 때 Enter → **끝 글자가 두 번 들어가거나 빠지지 않는지** P0 스파이크 ① 탭(입력 기록·글자 수 표시)으로 확인. 문제가 있으면 제출 시 조합 확정 후 한 프레임 늦게 처리 |
| 한/영 전환 | 터미널에 명령 입력할 때 한글 상태면 `ㅎㅑㅅ` 같은 입력이 됨 → **`ㅎㅑㅅ`, `햣`처럼 git의 한글 자판 입력을 감지하면 "한/영 키를 눌러 영어로 바꿔줘" 안내** |
| 폰트 | exe: 본문은 `SystemFont`로 맑은 고딕(Windows 기본) / 웹판: 글꼴 파일 내장 필수. 터미널: **D2Coding**(오픈 폰트 라이선스, 한글 고정폭) 내장 → 한글·영문 폭이 맞아 터미널 정렬 유지 |
| 테스트 | exe와 웹판(Edge·Chrome) 각각에서 커밋 메시지, 충돌 편집기, 닉네임 입력을 P0에서 확인 |

> 💡 **한/영 전환 감지**는 Windows 교실에서 특히 효과가 크다. 학생들이 가장 자주 겪는 "명령이 안 돼요"의 원인이다.

## 4. 엔진 선택 재확인 (Windows 전용 기준)

Windows만 대상이 되면 Unity·Godot의 **Windows 실행 파일**(WebGL 아님)도 후보가 된다. 다시 점수를 매겨도 결론은 같다.

| 항목 | 가중치 | Unity (Windows 빌드) | Unreal | Godot (Windows 빌드) | Web |
|---|---:|:---:|:---:|:---:|:---:|
| 학교 배포 (설치 불가·복원 프로그램·exe 실행 차단 가능성) | 25 | 3 | 1 | 3 | 5 |
| 저사양 Windows PC | 15 | 4 | 1 | 5 | 5 |
| UI 제작 (터미널·그래프·편집기) | 15 | 3 | 2 | 4 | 5 |
| 한글 입력 | (UI에 포함) | Windows 빌드는 양호 | 양호 | 양호 | 양호 |
| 개발 비용 | 10 | 4 | 2 | 5 | 4 |
| 인력 수급 | 10 | 5 | 3 | 2 | 5 |
| 멀티플레이 | 10 | 4 | 5 | 3 | 4 |
| 시각 연출 | 5 | 4 | 5 | 3 | 2 |
| 실제 Git 연동 | 5 | 4 | 3 | 3 | 5 |

| **합계 (100점)** | | **73** | **44** | **72** | **93** |

- Windows 실행 파일은 설치 없이 폴더째 실행할 수 있지만, 학교 보안 정책상 **exe 실행 자체가 막히는 경우가 많고**, 복원 프로그램 때문에 매번 다시 복사해야 한다.
- 점수상으로는 Web이 앞섰으나, **최종 결정은 Godot**이다 ([Godot 아키텍처 1.1](GODOT_ARCHITECTURE.md): 달라지는 점과 대응). Godot은 exe와 웹판을 둘 다 만들 수 있어 위 배포 감점은 "exe가 막히면 웹판, 인터넷이 막히면 exe"로 보완한다.

## 5. 에필로그: 실제 Git을 Windows에서 쓰기

게임을 마친 뒤 실제 PC에서 Git을 쓰는 단계. **게임 터미널과 최대한 같은 환경**을 만드는 것이 목표다.

### 5.1 설치 방법 선택
| 방법 | 관리자 권한 | 복원 프로그램 영향 | 추천 상황 |
|---|---|---|---|
| **Git for Windows (설치판)** | 필요 | 교사가 기본 이미지에 미리 설치하면 유지 | 컴퓨터실 정식 도입 |
| **PortableGit (휴대용, 압축 해제만)** | **불필요** | 재부팅 시 사라짐 → 공유 폴더/USB에 두고 사용 | 설치 권한이 없을 때 |
| 이미 설치된 PC | — | — | 학교 정보실 PC 확인 |

> 📌 가장 좋은 방법은 **정보 교사가 전산 담당과 협의해 Git for Windows를 컴퓨터실 기본 이미지에 넣는 것**이다.

### 5.2 Git for Windows 설치 시 권장 선택 (교사가 미리 확인)
| 설치 화면 | 권장 | 이유 |
|---|---|---|
| 기본 에디터 | **Notepad(메모장)** 또는 VS Code | 기본값 Vim은 학생이 빠져나오지 못함 |
| 첫 브랜치 이름 | **Override → `main`** | 기본값은 `master` + 긴 hint가 출력됨 (실험 확인). 게임·GitHub와 맞춤 |
| PATH | 기본값 (Git from the command line and also from 3rd-party software) | |
| 줄바꿈(Line ending) | 기본값 (Checkout Windows-style, commit Unix-style) | 아래 5.4 경고 안내 필수 |
| 터미널 | MinTTY (Git Bash 기본) | |

### 5.3 어떤 터미널을 쓰나 → **Git Bash 권장**
| 터미널 | `cd` `ls` `cat` | 한글 표시 | 판단 |
|---|---|---|---|
| **Git Bash** | ✅ 게임과 동일 | 양호 (`core.quotePath false` 설정 시) | **권장** — 게임 터미널과 같은 명령 |
| PowerShell | `ls`·`cat` 별칭으로 동작, 출력 모양 다름 | 오래된 버전은 한글 깨짐 가능 | 차선 |
| 명령 프롬프트(cmd) | `ls`·`cat` 없음 (`dir`·`type`) | 깨짐 잦음 | 비권장 |
| VS Code 터미널 | 기본 셸을 Git Bash로 지정 시 동일 | 양호 | 심화 (VS Code의 Git 화면과 비교 학습) |

### 5.4 첫 수업 설정 (학생이 직접 입력 — 게임 5-1 섬 설정과 연결)
```bash
git config --global core.quotePath false    # 한글 파일 이름이 "\352\264..."로 깨지지 않게
git config --global init.defaultBranch main # 새 저장소 첫 브랜치를 main으로
git config --global pull.rebase false       # 게임에서 한 것과 같은 pull 방식
git config --global core.editor notepad     # 에디터가 열리면 메모장으로
```
**사용자 이름은 공용 PC이므로 저장소마다 설정** (`--global` 쓰지 않음):
```bash
git config user.name "닉네임"
git config user.email "GitHub에 등록한 이메일"
```

**학생이 처음 보면 놀라는 메시지 (미리 알려줄 것)**
| 메시지 | 뜻 | 대응 |
|---|---|---|
| `warning: in the working copy of 'a.txt', LF will be replaced by CRLF the next time Git touches it` | Windows와 다른 OS의 줄바꿈 문자를 맞춰주겠다는 **경고(오류 아님)** | 무시해도 됨. "Windows는 줄 끝 표시가 달라서 Git이 알아서 맞춰주는 거야" |
| `hint: Using 'master' as the name for the initial branch...` | 첫 브랜치 이름 안내 | `init.defaultBranch main` 설정 |
| 에디터(Vim/메모장)가 갑자기 열림 | `-m` 없이 commit, 또는 merge/revert 메시지 작성 | 메모장이면 저장 후 닫기. Vim이면 `Esc` → `:wq` → Enter |
| 브라우저가 열리며 GitHub 로그인 요청 | 첫 push 시 Git Credential Manager가 로그인 처리 | 본인 계정으로 로그인 |

### 5.5 공용 PC 보안 (중요)
- 첫 push 때 GitHub 로그인 정보가 **Windows 자격 증명 관리자**에 저장된다. 그대로 두면 **다음 학생이 앞 학생 계정으로 push**할 수 있다.
- 수업 끝 체크리스트:
  1. 제어판 → **자격 증명 관리자 → Windows 자격 증명** → `git:https://github.com` 항목 제거
  2. 브라우저에서 GitHub 로그아웃
  3. (복원 프로그램이 있으면 재부팅으로 자동 초기화)
- `user.name`/`user.email`을 `--global`로 넣지 않는 이유도 같다 (다음 학생 커밋에 앞 학생 이름이 찍힘).
- 학생 GitHub 계정 생성은 GitHub 이용약관의 연령 기준과 학교 개인정보 지침을 확인한 뒤 진행한다. 계정을 만들지 않는 학급은 **로컬 Git 실습(챕터 1~4 내용)까지만** 진행하고, 원격 실습은 교사 계정의 저장소를 시연한다.

### 5.6 게임 ↔ 실제 Git 차이 안내표 (에필로그 시작 화면)
| 게임에서는 | 실제 Windows Git에서는 |
|---|---|
| 한글 파일 이름이 그대로 보임 | `core.quotePath false` 설정 필요 |
| `-m` 없으면 안내 메시지 | 에디터가 열림 |
| 줄바꿈 경고 없음 | LF/CRLF 경고가 보일 수 있음 (무시 가능) |
| 허브 섬 주소 `hub.versionland` | `https://github.com/<계정>/<저장소>.git` |
| 로그인 없음 | 첫 push 때 브라우저 로그인 |
| 출력이 항상 영어 | 대부분 영어 (설정에 따라 한국어로 나올 수 있음) |
