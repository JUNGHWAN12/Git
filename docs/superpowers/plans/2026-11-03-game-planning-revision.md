# 게임 기획 점검 반영 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자가 승인한 점검 7개 항목을 기존 기획 문서에 반영하고 문서 간 모순을 검증한다.

**Architecture:** Git 동작은 시뮬레이터 명세, 스테이지·별점·경로는 스테이지 명세, 온라인 개인/팀 목표는 협업 설계, 범위·일정은 구현 계획서를 기준으로 한다. GDD·README·기술·배포 문서는 각 기준을 요약한다.

**Tech Stack:** Markdown 문서 수정, Python 읽기 검증, 실제 Git 임시 저장소 확인.

**Spec:** 2026-11-03 대화의 게임 기획 점검 7개 항목 및 사용자의 “모두 반영해주세요” 요청.

## Global Constraints

- 이번 요청은 기획 문서 반영이다. 게임 기능 구현과 실제 학생 플레이테스트 결과를 완료했다고 보고하지 않는다.
- 기존 34개 스테이지 카드를 유지하고 첫 시범용 20개 경로를 구분한다.
- 조회·실패 명령·힌트·의도된 오류는 별점 감점 대상이 아니다.
- 실제 Git 동작을 교육용 진행 순서에 맞추어 위조하지 않는다.
- 기존 사용자 변경인 `.gitignore`, `game/project.godot`, `.mcp.json`, `AGENTS.md`는 수정하지 않는다.
- 시간 예산·개발 기간·재미는 실측 전 가설과 후속 검증 게이트로 표시한다.

## Review Focus

- 필수 경로가 생략한 이전 스테이지 없이 초기화·완료 가능한가.
- 협업 역할 교대 전후의 개인 목표가 서로 충돌하지 않는가.
- 조회·힌트·오류 체험 뒤에도 별점과 보스 행동 예산에 불이익이 없는가.
- 스냅샷 과제와 협업 모범 경로가 실제 Git에서 성립하며 명령 상한을 만족하는가.
- 전체 범위·시범 범위·미검증 배포 조합을 완료로 혼동하지 않는가.
