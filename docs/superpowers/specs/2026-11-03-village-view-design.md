# 2.5D 쿼터뷰 마을 뷰 설계

> 상태: 정식 마을 시스템은 설계 초안 (2026-11-03). 후속 점검에서 P0 시안의 에셋 누락 대체만 구현. 상태 연동·가변 배치·클릭 선택 등 정식 구현은 미완료.
> 범위: 마을 화면(작업장 시각화) 하나. 시뮬레이터·터미널·커밋 그래프·4개 공간 미니맵은 기존 2D UI와 로직 그대로다.

## 1. 목표와 성공 기준

- 건물 파일(`종류/색/층수/장식`)을 **3D 모델로 된 쿼터뷰 마을**로 보여 준다. Git 상태가 바뀌면 마을이 바뀌어 학습 피드백이 된다.
- 구도 확인용 시안(2026-11-03, `game/scenes/spike/village_spike.*`)에서 4개 구역이 쿼터뷰로 읽히고 색 틴트가 동작함을 확인했다.
- 성공 기준
  1. 같은 World 상태는 언제나 같은 마을이 된다 (배치가 결정적).
  2. 속성 변경(색·층수)이 즉시 모양에 반영된다.
  3. 에셋이 없는 PC에서도 대체 도형으로 마을이 그려진다.
  4. 학교 PC(Compatibility 렌더러)에서 부드럽게 돈다.

## 2. 이미 정한 것

| 항목 | 결정 |
|---|---|
| 표현 | 3D 모델 + 고정 정사영 카메라(쿼터뷰). MVP의 "3D 제외"는 **마을 연출에 한해 풀고**, 게임 규칙은 2D 로직 그대로 |
| 속성 → 모양 | **종류=모델, 색=재질 틴트, 층수=모델 선택**, 장식=옆에 놓는 소품 |

| 에셋 | Cartoon City Massive Pack. 선별 모델은 **저장소에 올리지 않고 로컬에만** 둔다 |
| 스펙 변경 | 건물 종류 11가지를 팩에 맞춤 (3장) |

## 4. 구성 요소

| 단위 | 하는 일 | 의존 |
|---|---|---|
| `village_view` (`Node3D`) | `Session.world_changed`를 받아 파일 목록을 이전과 비교해 건물을 추가·갱신·제거한다. World는 읽기만 한다 | `Session`, `layout`, `building_node` |
| `layout` (순수 함수) | 구역·건물 목록 → 건물별 월드 위치. 노드를 만들지 않는다 | 없음 |
| `building_registry` | `종류 → {모델 경로 목록, 배율, 발자국(footprint), 대체 도형}` 표. 모델 교체는 이 표만 고친다 | 없음 |
| `building_node` | 속성 사전 1개 → 건물 1채(모델, 틴트, 층수 모델, 장식 소품) | `building_registry` |
| `village_camera` | 정사영 카메라를 쿼터뷰 각도(-35.264°, 45°)로 고정하고, 클릭한 건물을 레이캐스트로 찾아 신호를 보낸다 | 없음 |

속성 파싱은 기존 `core/building_file.gd`를 그대로 쓴다.

## 5. 배치 규칙 (결정적)

건물 파일에는 위치 정보가 없으므로 규칙으로 정한다.

- 구역(폴더)마다 땅 한 칸을 준다. 구역 칸의 위치는 구역 이름 순서로 정한다.
- 구역 안에서는 파일 이름순으로 격자 슬롯에 놓는다.
- **슬롯 크기는 건물 크기에 맞춰 가변이다.** 구역 안 건물 발자국의 최댓값(`building_registry`)을 슬롯 한 변으로 하고, 열 수는 `ceil(sqrt(건물 수))`로 한다. 구역 땅은 슬롯 격자에 맞게 계산한다.
- 시안 문제: 고정 슬롯(9m)에서는 8~10m 건물이 이웃과 겹치고 땅 밖으로 나갔다.

## 6. 속성 표현

- **색**: 모델 재질의 알베도에 색을 곱한다. 시안에서 파랑·빨강·노랑·초록이 잘 구분됐다. 금색·검정은 구현 때 확인한다. 팩 재질이 공유 텍스처라 모델마다 재질 복사본을 만든다.
- **층수**: 스케일이 아니라 **모델 선택**이다. 1층 3.4m, 2층 6.2m, 3층 8.7m, 4~5층 10.3m. 건물 종류 중 집만 해당한다.
- **장식**: 꽃, 등불, 리본은 건물 옆에 소품을 놓는다. 소품 모델은 `Nature and Park`에서 고른다 (구현 때 선별).
- **깨진 건물(지지직)**: 파싱 실패 시 종류를 알 수 없으므로 공용 대체 도형에 글리치 셰이더를 씌운다.

## 7. 에셋 반입

- `tools/import_pack`이 팩 폴더 경로를 받아 사용 목록의 모델과 공통 재질·텍스처를 `game/Cartoon City Massive Pack/`로 복사한다. 이 폴더는 `.gitignore` 대상이다.
- git에는 **사용 목록(manifest)**만 올린다. 다른 PC는 팩을 갖고 있으면 스크립트로 복원한다.
- 용량: 모델은 4~160KB로 작다. 텍스처(아틀라스 약 550KB 외 몇 장)가 대부분이고, 목표는 선별 에셋 합계 50MB 안쪽이다.
- 에셋이 없으면 `building_registry`의 대체 도형(색 상자, 원기둥)으로 그린다.

현재 시안은 `village_spike.gd` 내부에서 모델 존재 여부를 확인하고, 없으면 상자·원기둥으로 대체한다. `--no-pack` 옵션으로 에셋이 있어도 이 경로를 검증할 수 있다. `building_registry`, manifest와 `tools/import_pack`은 정식 구현 계획이며 아직 작성되지 않았다.

## 8. 연출과 테스트

- 연출(MVP): 건물이 생기거나 속성이 바뀌면 짧게 커지는 Tween, 삭제 시 작아지며 사라짐, 포털 이동 시 페이드. 환경 애니메이션은 Should로 미룬다.
- 렌더링: Compatibility 렌더러, 방향광 1개, 후처리 없음.
- 테스트 (기존 `tests/run_tests.gd`, 헤드리스)
  1. `layout`이 같은 입력에서 같은 위치를 내는지, 건물이 슬롯과 구역 땅을 벗어나지 않는지.
  2. `building_registry`가 종류 11가지를 모두 갖는지.
  3. 에셋이 없을 때 대체 도형이 나오는지.
  4. 파싱 실패 파일이 깨진 건물이 되는지.
  5. `test_scripts_compile`이 새 GDScript도 검사한다.
- 화면 품질은 자동 테스트로 못 잡는다. 구현 후 실행해 스크린샷으로 한 번 확인한다.

## 9. 미결 사항

1. **용어 충돌**: 건물 종류 "나무"가 커밋 그래프의 "자라는 나무"와 겹친다. "정원수"나 "가로수"로 바꿀지 결정해야 한다.
2. **표지판 모델**: `Sign_C_1`이 시안에서 검게 나왔다. 대체 모델을 고르거나 재질을 고쳐야 한다.
3. **소품 가독성**: 벤치·가로등·표지판이 작다. 배율을 키우거나 선택 표시(윤곽선·하이라이트)가 필요하다.
4. **구역 라벨**: 건물에 가려진다. 위치나 크기를 조정한다.
5. **라이선스**: 팩의 재배포·웹 게시 허용 여부를 itch.io 구매 페이지에서 확인해야 한다. 웹 배포는 모델이 공개되므로 더 엄격히 본다.
6. **웹 데모**: 한글 입력 검증이 먼저다 (P0). 웹 프리셋(`export_presets.cfg`)이 아직 없다.

## 10. 범위 밖

- 카메라 패닝·줌·회전, 날씨·환경 애니메이션, 차량과 군중, 캐릭터 애니메이션 (NPC는 별도 설계).
- 커밋 크리스탈과 깃토리(부엉이) 모델 (팩에 없음, 별도 제작).
- 3D 규칙 로직. 게임 규칙은 시뮬레이터가 맡는다.
