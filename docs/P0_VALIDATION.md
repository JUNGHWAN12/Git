# P0 검증 기록

> 2026-11-12 기준. 로컬 자동 검증은 P0의 일부이며 학교 현장 통과를 뜻하지 않는다. 학교 현장 결과는 아래 "학교 현장 검증"에 따로 기록한다.

## 로컬 검증

| 항목 | 결과 | 범위·제한 |
|---|---|---|
| 엔진 | `4.7.2.stable.official.ed1daf0bf` | Windows 표준판 콘솔 실행 파일 |
| 헤드리스 테스트 | 19개 통과, 실패 0 | 한/영 감지 5, 건물 파일 6, 통신 3, 마을 시안 4, 컴파일 1 |
| 에셋 누락 회귀 | 11개 종류의 도형 생성, 집 층수 차이, 구역 건물 수·틴트 확인 | 없는 모델 경로 자동 대체와 `use_pack_models=false` 모두 검사 |
| 장면 시작 | 기본 P0·모델 마을·`--no-pack` 마을 모두 오류 없이 종료 | 각 60프레임 헤드리스 실행, 종료 코드 0 |
| 마을 화면 | 모델 사용·대체 도형 두 경로의 스크린샷 확인 | 로컬 RTX 3090·Compatibility. 색상·층수 차이와 4개 구역 확인. 라벨과 건물 겹침은 기존 시안 한계로 남음 |

실행: 저장소 루트에서 `godot --headless --path game --script res://tests/run_tests.gd`. Windows는 실제 Godot 콘솔 exe 경로를 사용한다. 로그의 `RESULT: passed=19 failed=0`과 종료 코드 0을 확인했다.

화면 시작 점검은 `--headless --path game --quit-after 60`으로 기본 장면, `res://scenes/spike/village_spike.tscn`을 지정해 마을 시안을 검사한다. 에셋 없는 경로는 마지막에 `-- --no-pack`을 추가한다. 헤드리스 실행은 화면 품질·IME·GPU 성능을 검증하지 않는다.

## 학교 현장 검증 (2026-11-12)

담당자가 현장에서 관찰해 보고한 결과다. 스크린샷·로그 등 별도 증거 파일은 없다. 시험 파일은 Godot 4.7.1 내보내기 템플릿으로 만든 서명 없는 단일 exe(`CommitCraft.exe`, 약 104MB, 커밋 `efaf551` 기준)이다.

| 환경 항목 | 기록 |
|---|---|
| 학교·검증 일시·담당자 | 정보실습실, 2026-11-12. 학교명·담당자 미기록 |
| Windows 버전·CPU·GPU·RAM | Intel Core i7-8550U 1.80GHz, 8GB. Windows 버전·GPU 미기록 |
| 해상도·화면 배율·한국어 IME | 1366×768, 배율 125%. IME 종류 미기록 |
| 선정 배포 1종·서버 1종 | 시험한 조합: Windows exe + 교실 서버(선생님 PC, TCP 8910). 최종 선정은 미기록 |
| 개발·교육·서버 담당 및 각자 주당 시간 | 미기록 |

남은 일:

- **로딩 시간 재측정.** 경고 창을 넘긴 뒤부터 첫 화면까지, 그리고 두 번째 실행을 따로 잰다. 그래도 5초를 넘으면 원인(공유 폴더·USB 실행, 백신 검사, 104MB exe 읽기)을 줄이거나 예산을 조정한다.
- "PC 보호" 창은 서명 없는 exe에서 계속 뜬다. 수업 안내에 넘기는 방법을 넣거나 코드 서명을 검토한다.
- 커밋 500개 이상의 그래프 성능은 P0 기준 밖이다. 긴 스테이지를 만들 때 화면 밖 커밋 그리기 생략 등을 고려한다.
- 학생 PC 3대 이상의 동시 접속은 다음 현장 방문이나 P5 교실 부하 시험에서 확인한다.
- 미기록 항목(학교명·담당자, Windows 버전, 담당자별 주당 시간, 배포·서버 최종 선정)을 채운다.

P0 통과 여부와 일정 재산정은 [구현 계획서](IMPLEMENTATION_PLAN.md#p0-기술-스파이크-1주)의 선택 조합 및 기록 조건에 따라 판단한다. 학생 2명의 로컬 통신 시험은 교실망·30명 부하·push/fetch 협업 검증을 대체하지 않는다.
